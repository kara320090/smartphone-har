# 원고 v8 설명과 질의응답

2026-10-19 · 논문 본문·표·그림과 같은 근거를 사용한다.

## 60초 설명

스마트폰으로 활동을 기록할 때 이동 중인지, 앉거나 서 있는지, 누워 있는지를 표시하는 기능과 계단·앉기를 세밀하게 기록하는 기능은 필요한 정보가 다릅니다. 저희는 네 신경망의 기존 6종 행동 예측을 세 상태로 변환하고, 분류 오류가 실제 요약 출력까지 바꾸는지 확인했습니다. 같은 개발 사람 분할에서 세부 오류의 98.1~99.9%는 동일 상태 안의 혼동이었습니다. 따라서 6종 점수만 보고 제외할 수 있는 작은 RNN도 큰 활동 요약에는 후속 검증 후보가 됩니다. 다만 더 쉬운 과제의 점수이지 원래 모델 성능 향상은 아닙니다. 이 연구가 제시하는 것은 서비스가 필요한 상태를 먼저 정하고 그 수준의 오류와 모델 규모로 후보를 고르는 기준입니다. 실제 앱과 연속 기록은 다음 검증 단계입니다.

## 질문과 근거

**1. 그냥 클래스를 묶어서 점수가 높아진 것 아닌가요?**

맞습니다. 6종 성능 개선이라고 주장하지 않습니다. 같은 상태 안의 혼동과 상태 간 혼동을 구분해, 활동 요약이라는 사용 목적에서 어떤 오류가 출력까지 바꾸는지 정량화한 것입니다. 쉬운 과제에서 순환 신경망이 꼭 필요한지는 단순 특징·선형 기준과 추가 비교해야 합니다.

**2. 실제로 무엇에 쓸 수 있나요?**

준비된 센서 구간을 이동 / 앉거나 서 있음 / 누워 있음으로 표시하는 기능의 후보 모델을 고를 수 있습니다. 큰 상태만 필요한 표시에는 세부 오류를 모두 동일하게 취급할 필요가 없습니다. 단, 큰 상태 표시의 허용 오류와 기기 자원은 실제 사용 목적에 따라 별도로 정해야 합니다.

**3. 앱이나 하루 활동 기록을 만들었나요?**

아닙니다. UCI의 전처리된 구간과 저장 예측을 분석했습니다. 실제 스마트폰 입력, 연속 기록, 중복 구간 처리, 지속시간 오차를 검증한 자료는 아닙니다. 그림 1은 분석 절차와 활용 제안입니다.

**4. LSTM 담당인데 왜 작은 RNN도 제시하나요?**

활용 목적에 따른 공정한 후보 선정이 연구 질문이므로 네 모델의 실제 결과를 함께 보고했습니다. RNN은 세부 6종 F1 0.7191이지만 3상태 F1 0.9960입니다. 1,542개 파라미터라는 규모가 후보 검토 이유이며 속도·전력·동등성의 증거는 아닙니다.

**5. LSTM에서 확인한 것은 무엇인가요?**

기준 L01은 21,222개 파라미터로 6종 F1 0.8813±0.0195, 3상태 0.9980±0.0012입니다. CNN보다 파라미터가 75.2% 적고 6종 F1 평균 차이는 0.0076입니다. 소형 L02는 6,630개로 3상태 0.9982±0.0005였으나 기준 L01을 대체하지 않았습니다. LSTM 수학·저장복원·초기값·세 seed별 세부 결과는 기존 LSTM 보고서에 보관했습니다.

**6. 622회 중 610회는 무엇을 뜻하나요?**

같은 검증 1,775구간을 L01 세 seed 모델이 각각 예측한 6종 오류 사건의 합계가 622회입니다. 이 중 610회는 같은 상태 안의 혼동이고 12회는 상태 간 혼동입니다. 새로운 사용자나 독립 표본 622개라는 뜻은 아닙니다.

**7. 표의 ±는 신뢰구간인가요?**

같은 사람 분할에서 세 seed 결과의 표본 표준편차입니다. 사람 모집단 신뢰구간이나 실제 사용자 성능의 보증이 아닙니다.

**8. 데이터 누출이나 test 사용은 없나요?**

저장된 학습 통계로 한 번 표준화했고 사람·표본 ID를 분리했습니다. 다만 validation은 epoch 선택에도 사용했으므로 독립 test와 구분해야 합니다. 공식 test는 이번 분석에서도 평가하지 않았습니다. 매핑은 사후 분석으로 적었습니다.

**9. 앉은 시간·수면·계단 횟수를 알 수 있나요?**

이번 세 상태만으로는 알 수 없습니다. 앉기와 서기, 걷기와 계단을 합쳐 구분 정보가 사라지고, 누워 있음은 수면이 아닙니다. 연속 기록과 목적에 맞는 세부 라벨 검증이 필요합니다.

**10. 앞선 연구와 비교한 새로운 점은 무엇인가요?**

새로운 알고리즘이나 최고 성능을 주장하지 않습니다. 팀의 동일 개발 분할·저장 예측에서 세부 오류를 활동 요약 출력과 연결하고, 작은 모델도 목적에 따라 검토할 수 있다는 구체적 근거를 제시합니다. 사후 탐색·단일 분할이라는 한계가 있어 추가 검증 전 일반화나 실서비스 완성을 주장하지 않습니다.
