# v10 발표·심사 질의응답

## 이 논문으로 무엇을 결정할 수 있는가?

활동 기록이 요구하는 출력 수준부터 결정할 수 있다. 이동/앉거나 서 있음/누워 있음만 필요할 때는 같은 입력과 목표에서 통계·선형 기준선을 먼저 확인한다. 계단·앉기 같은 세부 구분이 필요하면 6종의 오류를 따로 검토한다. 이번 결과는 허리 착용 UCI HAR에서의 모델 선택 근거다.

## 단순히 클래스를 줄여 점수를 높인 것 아닌가?

과제가 쉬워지는 효과가 포함된다. 그래서 6종 F1, 6종 예측을 3상태로 병합한 F1, 처음부터 3상태를 학습한 F1을 나란히 제시한다. 큰 상태가 서비스 목표일 때 어떤 학습 구성이 필요한지를 비교하며 원래 6종 문제를 해결했다고 주장하지 않는다.

## 병합은 확률을 더한 것인가?

이번에 고정한 방식은 6종 argmax 클래스의 상태 매핑이다. 세 그룹의 확률을 합한 뒤 argmax를 고르는 방식과 일반적으로 같지 않다. 후자는 이번 고정 비교에 포함하지 않았다. test를 본 뒤 유리한 병합 방식으로 교체하지 않았다.

## LR와 신경망은 입력이 달라 불공정하지 않은가?

LR와 시계열 NN 비교에는 표현 차이가 있다. 이를 보완하려고 LR3와 FMLP3에 동일한 채널별 평균·표준편차 18개와 동일한 특징 표준화 통계·3상태 정답을 제공했다. 최적화·용량·수치형은 같지 않으며, 이는 지정한 두 구성의 비교다.

## 동일 seed이면 모든 조건의 초기 가중치도 같은가?

아니다. 이번 직접 3상태 대조는 같은 seed와 학습 설정을 사용하지만 6출력과 3출력 모델의 전체 초기 가중치 일치를 주장하지 않는다. 과거 L01/L03의 초기 가중치 복사 통제와 구분한다. 같은 seed의 점수 차이는 보충 CSV에 제공한다.

## test 결과를 보고 모델을 골랐는가?

개발 비교·CPU 측정을 마치고 모델 29개와 코드·통계·개발 결과 271개 파일을 고정해 GitHub에 커밋한 다음 공식 test를 평가했다. 이후 모델 재학습·설정 변경·최고 seed 선택은 없었다. 추가 조건 자체는 이전 개발 결과를 본 뒤 정했으므로 연구 전체가 사전등록된 것은 아니다.

## 누출과 높은 점수는 어떻게 확인했는가?

학습 16명, 검증 5명, test 9명을 분리했다. 표준화는 학습 통계만 사용했고 공식 원본 센서·라벨·사람과 캐시의 원 행을 대조했다. 겹치는 구간이 있으나 사람 단위 분리다. 높은 3상태 점수는 쉬워진 과제·제한된 데이터 조건에서의 결과이며 일반 환경을 보장하지 않는다. LR3도 test 2건을 틀렸다.

## 0.9994는 정확도 99.94%인가?

아니다. 0.9994는 Macro F1이다. LR3 Accuracy는 2,945/2,947=0.999321…이다. NN은 세 seed 평균과 표본 SD, LR는 단일 적합 결과로 보고한다.

## 세 seed로 통계적 우월성이나 동등성을 말할 수 있는가?

이번에는 기술 통계만 보고한다. 같은 test 사람에서의 seed SD는 새 사람 모집단의 신뢰구간이 아니다. 비열등성·동등성 검정이나 다중 비교 유의성 검정을 수행하지 않았다. 각 사람의 점수와 사례를 보충자료에 제공한다.

## 0.073ms면 스마트폰 실시간 처리가 되는가?

현재 PC에서 준비된 128×9 센서 구간을 입력받아 표준화·특징·분류·확률·클래스 반환까지 측정한 값이다. 50Hz의 128시점은 2.56초 입력 창이고 창 간격은 1.28초다. 수집·필터링·구간화·초기 로딩과 기기 전력은 별개다. LR는 NumPy, NN은 TensorFlow여서 구현 차이도 포함된다.

## 메모리 816바이트가 실행 메모리인가?

LR3의 수치 가중치·편향·두 단계 전처리 배열 합계다. 런타임·객체·작업 배열은 제외한다. 전체 프로세스 RSS는 약 330MiB로 별도 기록했으며, 관측한 RSS 최대치도 순간 할당 피크를 보장하지 않는다.

## 실제로 핸드폰 센서만으로 무엇을 할 수 있는가?

허리 착용 스마트폰의 가속도·각속도만으로 세 활동 상태를 분류할 수 있음을 이 공식 test에서 확인했다. 카메라·GPS 없이 활동 상태 표시 모듈을 구성할 후보 근거다. 앱과 하루 활동 지속시간 집계는 구현하지 않았고 눕기를 수면으로 해석하지 않는다.

## LSTM 담당자의 실질 기여는 무엇인가?

기존 LSTM 구현·수학 검증·9회 개발 실험을 수행했고, 이번에는 LSTM 직접 3상태 3회와 팀 공통 보완 대조·고정·공식 test 감사·논문 취합을 추가했다. 역할별 기존 모델 구현 기여를 유지하며 후속 공통 평가를 특정 팀원의 독립 모델 구현처럼 기재하지 않는다.

## test 공개 후 다음 개선은 어떻게 하는가?

현재 결과를 그대로 보고한다. 이 test에 맞춰 다시 튜닝한 결과는 같은 의미의 최종 독립 평가가 될 수 없다. 다른 기기·휴대 위치·연속 신호의 새 검증 데이터를 확보하고 별도 프로토콜로 평가한다.
