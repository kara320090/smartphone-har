## 1 공동 주제와 제출 목표

가제는 **스마트폰 센서 기반 행동 인식 모델의 사용자 독립 성능 및 안정성 비교**다. 학습에 포함되지 않은 사람의 행동을 분류할 때 MLP, 1D CNN, LSTM의 성능과 변동이 어떻게 다른지 비교한다. UCI HAR의 기존 자료를 사용하며 새로운 참여자 모집이나 센서 측정은 기본 범위에 포함하지 않는다.

| 구분 | 범위 |
|---|---|
| 핵심 비교 | 동일한 128×9 센서 구간을 사용하는 시계열 MLP, 1D CNN, LSTM |
| 보조 비교 | 561특징 MLP. 입력 표현이 다르므로 별도 참고 결과로 구분 |
| 보조 분석 | MLP 초기 가중치 일치 대조, 전처리·저장물 검증 |
| 우선 지표 | 6클래스 Macro F1, Accuracy, 클래스별 F1, 사람별 성능 |
| 구현 부담 | 파라미터 수, 같은 장치·측정 범위의 추론 시간 |
| 이번 논문에서 선택 사항 | 단순 RNN, 선형 모델, PCA·군집 추가 분석, AE의 분류 활용 |

AE의 재구성 MSE를 분류 F1과 같은 순위표에 넣지 않는다. 기존 수업 프로젝트의 PCA·군집·RNN·AE 등 학습 과제는 유지하되, 1~2쪽 논문에 모두 담을 필요는 없다. CNN이나 LSTM이 MLP보다 좋다는 결론을 미리 정하지 않는다.

2026년 10월 9일 확인한 공식 공고상 대학생 논문은 **대학생 전용 양식, 2단 편집 1~2쪽**이며, 대학생 발표는 포스터다. 논문 마감은 10월 26일이고 대학생 등록비는 6만 원이다. 분야의 성격은 AI+X 융합 기술에 해당하며 제출 화면의 대학생 분류와 실제 선택 항목에 맞춰 입력한다. 참가 자격과 저자 구성은 팀에서 최종 확인한다. [공식 모집 안내](https://dcs.or.kr/homepage/custom/submit)

## 2 역할별 책임과 인계 순서

| 담당 | 작업 책임 | 반드시 넘길 결과물 | 논문에 작성할 부분 |
|---|---|---|---|
| ① 정회서 | 데이터 분석·전처리·사람 분할 | 로더, 데이터 사전, 분할 목록, 전처리 통계, 분포표 | 데이터셋, 전처리, 누출 방지 |
| ② 이봉헌 | MLP·공통 학습·재현성·팀장 | MLP 실행 묶음, 공통 학습 코드, 설정 규약, 검증 기록 | 기준모델, 학습 절차, 재현성, 서론·결론 취합 |
| ③ 유재윤 | CNN·LSTM 구현과 구조 분석 | 모델 코드, 구조표, 연결 검사, 모델별 설명 | 비교 모델 구조, 선정 이유, 복잡도 |
| ④ 한윤섭 | 실험 설계·반복 실행 관리·평가 | 실행 대장, 비교 CSV, F1·혼동행렬·사람별 분석 | 실험 설정, 비교 결과, 오류와 한계 |
| ⑤ 최승빈 | 공통 추론·저장물 통합·시간 측정·시연 | 추론 함수, 재로딩 기록, 시간 원자료, 시연 | 추론 절차, 효율성, 통합 검증 |

①의 입력을 ②·③이 사용하고, 모델과 설정을 ④가 같은 평가 규칙으로 비교한다. ⑤는 동일 실행 폴더의 모델·전처리·메타데이터를 함께 받아 검증한다. ④가 공식 실행 대장을 관리하고, 실제 학습은 ②·③에게 배분할 수 있다. 같은 run_id를 두 사람이 중복 실행하거나 서로의 결과를 덮어쓰지 않는다.

## 3 정회서 담당 데이터와 전처리

### 작업

- UCI 공식 파일의 특징·시계열·정답·사람 ID·표본 ID가 같은 행을 가리키게 로딩한다. 사람 ID는 분할과 분석에만 쓰고 모델 입력에는 넣지 않는다.
- 클래스와 사람별 구간 수, 입력 차원, 채널 순서, 결측·비유한 값 여부를 정리한다.
- 공식 train의 사람 21명 안에서 개발용 fit/validation 분할을 만든다. 기존 검증 사람 `[1,6,14,21,23]`을 S0으로 보존한다. 추가 S1·S2의 명시적 사람 목록은 ④와 결과를 보기 전에 확정한다.
- 각 분할의 fit 자료만으로 평균·표준편차와 필요한 PCA를 fit한다. S0의 전처리 통계를 S1·S2에 재사용하지 않는다.
- 모든 분할에 클래스가 존재하는지, fit/validation 사람·표본 교집합이 없는지 검사한다. S1·S2의 구간 수가 S0과 같을 필요는 없다.
- PCA·군집 그림은 데이터 탐색과 수업 산출물로 보관한다. 실제 설명분산을 계산하여 보고하고, 고정 100차원이 항상 95%를 보존한다고 가정하지 않는다.

### 결과물과 완료 기준

| 결과물 | 포함할 내용 | 완료 기준 |
|---|---|---|
| 로더·전처리 코드와 실행 안내 | 원 파일 경로, 반환 키, 처리 순서 | 다른 담당자가 개발용 작은 묶음을 로드 가능 |
| `data_dictionary.md` | shape, dtype, 단위, 채널·라벨 순서, ID 기준 | 배열 열과 모델 입력을 설명 가능 |
| `splits/S0.json` 등 | fit/validation 사람·sample_id 목록, 생성 규칙 | 실제 실행과 동일한 목록이며 중복 검사 통과 |

원고는 “UCI HAR 데이터를 사용하였다”에서 끝내지 않고, 어떤 입력을 사용했고 어떤 사람을 학습·검증에서 분리했는지, 어느 자료로 통계를 계산했는지 설명한다. 예: “채널별 평균과 표준편차는 각 분할의 학습 자료에서만 추정하고, 동일한 통계를 검증 자료에 적용하였다.” 실제 구현을 확인한 경우에만 이 문장을 사용한다.

## 4 이봉헌 담당 MLP와 공통 학습 및 취합

### 작업

- 시계열 MLP를 주요 기준으로 제공한다. `(N,128,9)` 입력을 모델 내부에서 펼쳐 분류한다. 기존 E03을 활용할 수 있으나 새 팀 전처리와 연결한 결과는 별도 실행 ID로 검증한다.
- 561특징 MLP E02는 별도 입력 표현의 보조 기준으로 유지한다. 같은 입력의 구조 비교와 같은 표에 섞어 해석하지 않는다.
- ③의 Keras 모델을 공통 trainer에 연결한다. 입력·출력·loss·label·seed 설정 시점과 저장 규약을 확인한다. 현재 CLI가 MLP만 생성하는 부분은 모델 선택 연결이 필요하다.
- 전처리·sample_id 변환, 학습·저장·재로딩 검증을 ①·⑤와 함께 확인한다. 변경 전후 결과를 근거 없이 동일하다고 처리하지 않는다.
- 공통 설정, 실행 환경, 초기화 seed·셔플 seed·Dropout 관련 설정, 최선 epoch 선택 규칙을 기록한다. 서로 다른 모델 구조의 초기값을 모두 같게 만들었다고 표현하지 않는다.
- 수동 역전파와 자동미분 비교, 실제 입력 오류 수정, 기존 초기값 대조를 재현성 자료로 정리한다. 전체 HAR 학습은 Keras 자동미분을 사용했다는 범위를 유지한다.
- ④와 실험 계획·최종 평가 정책을 확정하고 중간 진행을 취합한다. 각 역할 원고를 한 논문 문체와 용어로 편집한다.

### 결과물과 완료 기준

| 결과물 | 포함할 내용 | 완료 기준 |
|---|---|---|
| MLP·공통 학습 코드 | 모델 생성, 설정, loss, early stopping, 저장 | CNN·LSTM도 같은 경로에서 연결 검사 가능 |
| 기준모델 실행 묶음 | config, split, history, model, preprocess, predictions, metrics | ④의 지표 재계산과 ⑤의 재로딩에 사용 가능 |
| `training_protocol.md` | 통제 조건, 설정 변경·탐색 규칙, 버전 | 전원이 같은 실험을 식별 가능 |
| 재현성 기록 | 역전파 검사, 입력 검사, 초기화 대조의 범위 | 실제 결함과 의도적 대조를 구분 |
| 개인 원고 | MLP 구조·파라미터 수·공통 학습·검증 | 실제 새 실행과 기존 결과를 구분 |
| 취합본 | 전체 원고, 참고문헌, 표·그림, 저자 정보 | 전원 검토 후 제출 가능한 한 파일 |

기존 24회 후속 학습은 MLP 중심의 결과이며, 팀 전체의 CNN·LSTM 비교가 완료되었다는 근거로 쓰지 않는다. 기존 결과와 새 결과의 전처리·분할·설정이 같다는 확인이 없으면 한 평균으로 합치지 않는다.

## 5 유재윤 담당 CNN과 LSTM

### 작업

- 핵심 비교용 1D CNN과 LSTM을 우선 구현한다. 두 모델 모두 같은 `(N,128,9)` 입력과 6개 logits 출력을 사용한다.
- 모델 생성 함수, 층별 출력 shape, 필터·커널·hidden size·활성화·Dropout·파라미터 수를 기록한다. 이 문서에서 아직 구현하지 않은 구체적 층 수를 완료 사실로 정하지 않는다.
- MLP·CNN·LSTM이 센서 구간을 처리하는 방법의 차이를 설명한다. LSTM이 더 우수하다는 식의 결과 예측을 논문 결과로 쓰지 않는다.
- 각 모델의 작은 입력 연결 검사와 한 번의 실제 학습을 확인한 뒤 ②·④에게 넘긴다. ④가 배정한 공식 반복 실행을 담당한다.
- 구조나 학습률을 바꾼 경우 이전 결과를 덮어쓰지 않고 새 config_id를 사용한다. 논문에 포함할 후보와 탐색 예산은 실행 전에 합의한다.
- 단순 RNN·AE는 수업 계획에 따라 별도로 진행한다. 논문 핵심 비교가 끝나기 전에 모델 수를 계속 늘리지 않는다.

### 결과물과 완료 기준

| 결과물 | 포함할 내용 | 완료 기준 |
|---|---|---|
| CNN·LSTM 코드 | 생성 함수, 의존성, 입력·출력 정의 | 공통 trainer에서 loss·예측 생성 가능 |
| `architecture.csv` 또는 표 | 모델·층·출력 shape·주요 설정·파라미터 수 | 코드와 model summary가 일치 |
| 연결 검사와 실행 묶음 | 실행 명령, 설정, 저장 모델, 실패 시 로그 | ②·④가 재실행 가능한 상태 |
| 개인 원고 | 모델 선정 이유, 구조 차이, 실제 설정, 한계 | 교과서 정의뿐 아니라 구현을 설명 |

원고는 “CNN을 사용하였다”에서 끝내지 않는다. 실제 커널이 어느 축을 따라 이동하는지, LSTM이 어느 축을 순서로 처리하는지, 출력이 어떻게 6개 클래스로 연결되는지 설명한다. 모델 설명은 관련 원 논문이나 공식 문서를 인용한다.

## 6 한윤섭 담당 실험 설계와 성능 평가

### 작업

- ①·②·③과 분할·seed·모델·설정·평가 규칙을 결과 확인 전에 확정한다. 공식 실행 대장을 만들고 누가 어느 run을 실행할지 배분한다.
- 3모델 × 3학습 seed × 3사람 분할의 **27회 개발 실험을 기본 목표**로 잡는다. 분할별 수치, seed별 수치, 실패·재실행 사유를 모두 보존한다.
- 예측 CSV로 Accuracy, 6클래스 Macro F1, 클래스별 F1과 혼동행렬을 독립 재계산한다. 혼동행렬의 행은 정답, 열은 예측으로 통일한다.
- 같은 분할·seed의 모델 간 차이를 대응시켜 보고한다. 분할별 평균과 seed SD를 먼저 보여주고, 사람별 결과로 특정 사람에 편중된 성능인지 살핀다.
- 27개 실행을 독립적인 사람 27명처럼 취급하지 않는다. 서로 겹치는 개발 분할도 독립 표본이 아니다. 단순 SD를 모집단 신뢰구간으로 표시하지 않는다.
- 많이 혼동한 행동과 실제 오분류 sample_id를 연결한다. 관찰과 원인 추정을 구분한다.
- 최종 모델·설정·선택 규칙이 동결된 후 지정 담당자로서 공식 test 평가를 수행한다. test 점수를 보고 재튜닝하지 않는다.

| `experiment_register.csv` | run_id, 모델, 분할, seed, config, 실행자, 상태, commit, 결과 경로 | 계획한 run의 누락·중복·실패가 드러남 |
| `comparison.csv` | run별 Accuracy·Macro F1·최선/종료 epoch·파라미터 수 | 저장 예측에서 재계산한 지표와 일치 |
| `class_metrics.csv`, `subject_metrics.csv` | 클래스·사람별 지표와 support | 어떤 집계 단위인지 명시 |
| 그림·원자료 | 비교 그림, 혼동행렬, 수치 CSV | 축·단위·범례·run 출처가 있음 |
| 개인 원고 | 실험 설정, 핵심 수치, 대응 차이, 오류 분석, 한계 | 검증과 공식 test 결과를 구분 |

“A 모델이 좋았다” 대신 어느 분할·평가 집합에서 어떤 지표가 얼마나 달랐는지 쓴다. 예: “개발 분할 [S]에서 [모델]의 Macro F1은 [실측값]이었으며, [비교 모델]과의 차이는 [실측값]이었다.” 대괄호는 실제 결과가 생긴 뒤 채운다.

## 7 최승빈 담당 추론과 통합 검증

### 작업

- 같은 run의 모델·전처리·config·metadata를 묶어서 로드한다. 다른 run의 전처리를 임의로 붙이지 않는다.
- 공통 센서 입력에 대해 전처리, 모델 실행, 확률·클래스 반환까지 일관된 함수를 제공한다. 평가 모드 `training=False`로 실행한다.
- 정상 입력 및 잘못된 shape, 비유한 값, 채널 수 불일치의 처리 결과를 기록한다.
- 저장 전·후 예측과 표본 ID를 대조한다. 각 최종 모델을 전체 고정 검증 입력에서 확인하고 허용오차와 최대 차이를 남긴다.
- 속도는 같은 장치·라이브러리·스레드·batch size에서 측정한다. 워밍업 후 여러 회의 실제 측정값을 남기고 median·p95를 계산한다. 가속기 사용 시 비동기 실행 종료를 기다린 뒤 시간을 기록한다.
- 모델 추론만의 시간과 전처리까지 포함한 시간은 분리한다. 파일 읽기, UI, 최초 로딩을 포함했는지 명시한다.
- 저장된 UCI 구간의 예측을 보여주는 오프라인 시연을 준비한다. PC에서 측정한 시간을 스마트폰 실시간 성능으로 표현하지 않는다.

### 결과물과 완료 기준

| 결과물 | 포함할 내용 | 완료 기준 |
|---|---|---|
| 공통 추론 코드·실행 안내 | 입력 계약, 로딩, 전처리, 예측, 오류 처리 | ②가 다른 실행에서 재현 가능 |
| `reload_verification.json` | run_id, 표본 수, 허용오차, 최대 차이, 통과 여부 | 세 모델 각각 검증 |
| `latency_samples.csv`, `latency_summary.csv` | 모델, 반복 번호, ms, 측정 범위, median·p95 | 원자료에서 요약값 재계산 가능 |

속도를 논문에 포함할지 여부는 측정이 완료된 뒤 판단한다. 검증되지 않은 지연 시간이나 “실시간 가능” 문구를 먼저 넣지 않는다.

## 8 모두가 지킬 실험 기준

### 공통 입력과 개발 분할

시계열 입력은 float32 `(N,128,9)`, 정답은 int64 `0..5`다. 채널은 body_acc xyz, body_gyro xyz, total_acc xyz 순서다. 561특징은 보조 입력으로 분리한다. sample_id와 subject를 항상 함께 보존한다.

- S0: 기존 fit 16명 5,577구간, validation `[1,6,14,21,23]` 5명 1,775구간.
- S1·S2: 공식 train의 21명 안에서 다른 검증 사람 5명을 선택한다. 목록을 ①·④가 먼저 저장하고 결과에 따라 유리한 분할로 바꾸지 않는다. fit 사람은 나머지 16명이다.
- 공식 test: 9명 2,947구간. 개발 분할 생성·전처리 fit·설정 선택에 사용하지 않는다.
- 학습 seed: 2026·2027·2028. 분할 생성 seed와 학습 seed는 구분해 기록한다.

### 학습 정책과 비교 범위

첫 연결 검사는 기존 trainer의 Adam, batch 64, 최대 40 epoch, val_loss 기준 patience 6 및 최선 가중치 복원을 출발점으로 사용한다. 모델별 학습률 등 설정과 후보 수는 10월 11일까지 ②·③·④가 확정해 `training_protocol.md`에 적는다.

모든 모델에 같은 숫자를 넣었다는 사실만으로 공정성이 확보되는 것은 아니다. 고정 설정 비교로 진행하면 그 범위를 밝혀 쓰고, 튜닝을 한다면 모델별 동일한 사전 탐색 예산과 선택 규칙을 적용한다. 튜닝 run은 본 실험 27회와 구분해 추가 집계한다. 결과를 본 뒤 한 모델만 추가 튜닝하지 않는다.

개발 실험은 조기 종료와 비교에 같은 validation을 사용하므로 독립 최종 성능 추정치로 취급하지 않는다. 최종 test 평가의 대상은 각 모델의 동결된 설정이다. 기본안은 S0의 fit/validation 정책과 세 seed를 사용한 모델 묶음을 그대로 평가하는 것이며, S1·S2는 개발 단계의 민감도 분석으로 보고한다. 공식 train 전체 재학습을 선택하려면 epoch 결정·전처리 재fit 규칙까지 test를 보기 전에 별도 확정한다. 가장 잘 나온 seed만 골라 test를 평가하지 않는다.

원칙적으로 같은 설정·seed에 대해 test를 한 번 예측해 원자료를 고정하고 지표를 계산한다. 기술적 실패로 재평가하면 이유를 기록하며, test 결과에 맞춘 설정 변경과 구분한다. test 평가 시점이 수업의 기존 9주차 원칙과 충돌하면 지도교수·팀의 일정을 먼저 맞추고, 합의 전에는 개발 검증 결과만으로 범위를 명확히 작성한다.

### 최소 완료와 일정 변경

목표는 27회지만 전체 실행이 어려우면 10월 14일 연결 점검에서 **실행 시간과 가용 자원**을 근거로 범위를 조정한다. 축소안은 S0에서 세 모델·세 seed의 9회이며, 이 경우 다른 사람 분할의 안정성을 검증했다고 쓰지 않는다. 불리한 점수 때문에 조건·seed를 제외하지 않는다. 선택한 범위와 변경 사유를 전원에게 공유하고 원고에 반영한다.

## 9 현재 저장소에서 먼저 맞출 연결 항목

2026년 10월 9일 확인한 원격 커밋 `f943e41`에는 `src(1)/` 데이터·전처리 코드, 작은 샘플과 분석 그림이 추가되어 있다. 이는 파일 존재와 소스 읽기로 확인한 상태이며, 새 모듈을 공통 trainer와 연결하여 수치 일치를 검증한 상태는 아니다. 기존 MLP 검증 기록은 별도로 보존한다.

| 확인 항목 | 현재 코드상 차이 | 담당과 조치 |
|---|---|---|
| 반환 구조 | `src(1)/data.py`는 fit/val/test별 Xs·Xf, 참조 어댑터는 X_seq·X_features와 indices | ①·②가 얇은 변환 어댑터와 작은 표본 대조 작성 |
| 표본 ID | 새 데이터 코드의 행 번호는 0부터, 기존 학습 기록은 1부터 | ①·②가 행 번호 기준을 명시하고 변환표로 원본 행 확인. 문자열만 맞춰 붙이지 않음 |
| 저장 전처리 | seq_mean·feat_mean 등 키와 기존 `reference_npz_v1` 형식이 다름 | ①·②·⑤가 로더·metadata·검증기를 함께 연결 |
| 표준화 계산 | 통계 정밀도와 0에 가까운 표준편차 처리 방식이 다름 | ①·②가 최대 수치 차이와 정책을 기록. 새 통계를 옛 모델에 결합하지 않음 |
| PCA | 새 코드는 100차원 고정, 기존 조건은 설명분산 95% 기준 | ①이 실제 보존 비율 보고. 같은 조건이라고 가정하지 않음 |
| 공식 test | 새 로더는 test도 읽어 반환, 기존 참조 개발 로더는 기본적으로 미로딩 | ①·②가 개발·최종 평가 경로를 분리. 로딩과 평가·튜닝 사용을 구분 |
| 전체 캐시 | README에 `processed_data.npz`가 설명되어 있으나 확인한 커밋에는 없음 | ①이 생성 명령·로컬 경로·전달 방법 확인. 미전달을 완료로 표시하지 않음 |

따라서 논문 전체에 “팀의 모든 코드가 test 파일을 읽지 않았다”고 쓰지 않는다. 어떤 모듈이 로딩했는지와 성능 평가·모델 선택에 사용했는지를 정확히 기록한다. 파일을 로딩했다는 사실만으로 데이터 누출이 있었다고 단정하지도 않는다.

## 10 개인 원고 작성과 제출 방식

각자 **5~8개 문단 정도의 초안**을 공통 양식에 작성하고, 필요한 표·그림을 함께 낸다. 이는 팀 내부 취합용 분량이며 각자 학회용 1~2쪽 논문을 따로 제출하는 것이 아니다. 최종 논문 한 편 전체가 학회 양식의 1~2쪽이다.

원고에는 다음 내용을 포함한다.

1. 담당한 연구 질문과 작업 목적.
2. 실제 구현한 방법과 선택 이유.
3. 데이터 분할·모델·설정·seed 등 실험 조건.
4. 실제 결과 수치와 해당 run_id·파일 경로.
5. 결과의 해석과 비교가 성립하는 범위.
6. 실제 발생한 문제, 원인, 수정, 재검증. 없었다면 문제를 만들지 않고 수행한 검증을 기술.
7. 남은 한계와 다른 담당자에게 요청할 사항.
8. 사용한 선행연구·공식 자료의 정확한 출처와 본인 기여.

“공부했다·열심히 했다·성능이 좋았다”만 적지 않는다. 수행 방법과 확인 가능한 근거를 문장으로 설명한다. 수치가 없으면 `[측정 예정]`으로 표시하며 예상값을 결과표에 채우지 않는다. 고친 오류를 실제 HAR 학습에서 겪은 사고처럼 바꾸지 않고, 의도적 오류 주입은 해당 사실을 표시한다.

표·그림마다 제목, 축·단위, 비교 조건, 원자료 파일을 적는다. 화면 캡처만 제출하지 말고 수정 가능한 표 또는 수치 CSV와 그림 파일을 함께 낸다. 남의 문장·그림은 그대로 복사하지 않고 필요한 출처를 붙인다. AI 보조를 사용한 경우 실제 확인한 코드·계산·출처와 검토 범위를 기록하고 제출처의 표기 기준을 확인한다.

권장 개인 제출 폴더는 다음과 같다. 실제 생성될 산출물의 이름은 팀이 조정해도 되지만, 원고와 근거의 연결은 유지한다.

```text
contributions/01_data/          # ①
contributions/02_training/      # ②
contributions/03_models/        # ③
contributions/04_evaluation/    # ④
contributions/05_inference/     # ⑤
  contribution.md              # 개인 논문 원고
  evidence_index.md            # 주장·수치와 근거 경로 대응
  references.md                # 실제 확인한 참고문헌
  figures/                     # 그림과 원자료 위치
  README.md                    # 실행 방법·환경·남은 사항
```

코드는 저장소의 담당 모듈에 두고 개인 폴더에는 상대 경로·커밋을 적는다. 큰 모델·원 데이터·가상환경을 원고 폴더에 중복 업로드하지 않는다. 모델은 run 단위 보관 위치를 공유한다. 위 `contributions/`는 제안 경로이며 현재 생성 완료된 결과 폴더를 뜻하지 않는다.

## 11 하나의 논문으로 취합하는 방법

| 최종 논문 구성 | 주요 제공자 | 취합할 내용 |
|---|---|---|
| 제목·초록·서론 | 이봉헌 취합, 전원 검토 | 문제, 연구 질문, 선행연구와 범위, 실제 핵심 결과 |
| 데이터와 전처리 | 정회서 | 입력·사람 분할·표준화·누출 방지 |
| 모델과 학습 방법 | 이봉헌·유재윤 | MLP·CNN·LSTM 구조와 공통 비교 조건 |
| 실험 결과와 분석 | 한윤섭, 전원 수치 확인 | 모델별 성능·변동·오분류·한계 |
| 효율성과 재현성 | 최승빈·이봉헌 | 측정 완료된 속도와 저장·재현 검증 |
| 결론·참고문헌 | 이봉헌 취합, 전원 검토 | 확인한 결론과 제한, 원 출처 |

이봉헌이 중복 설명을 줄이고, 모델명·데이터명·표기·지표 자릿수·그림 번호를 통일한다. 한윤섭이 최종 표를 원자료로 재계산한다. 각 담당자는 본인 부분의 사실과 수치를 확인하고, 전원은 논문의 전체 주장과 제출 파일을 검토한다. 저자 순서·교신저자·발표자는 실제 기여와 팀·지도교수 협의를 통해 정하며 이 문서에서 임의로 확정하지 않는다.

2쪽 구성의 예는 1쪽에 문제·자료·방법, 2쪽에 핵심 결과표·분석·결론·참고문헌을 배치하는 것이다. 개인 보고서를 이어 붙여 5개의 파트 소개로 만들지 않고, 하나의 연구 질문에 답하는 흐름으로 편집한다. 자세한 코드·실행 기록·추가 그림은 저장소에 보관한다.
