# 추가 대조 및 공식 test 평가 계획

2026-10-19. 기존 개발 결과를 본 뒤 설계한 후속 연구이며, 연구 전체의 사전등록이라고 주장하지 않는다. 사용자가 이번 작업에서 공식 test 평가를 명시적으로 승인했다.

## 질문과 조건

1. 같은 18개 채널 통계 특징과 같은 직접 3상태 목표에서 LR3와 FMLP3를 비교한다.
2. 기존 MLP/CNN/RNN/LSTM의 출력층을 3개로 바꿔 직접 학습한 MLP3/CNN3/RNN3/LSTM3를 비교한다. 입력 표현이 다른 LR와의 비교는 전체 구성의 비교이며 순수 구조 효과가 아니다.
3. 기존 6종 모델 4종×3seed와 LR6도 고정된 저장 모델로 공식 test의 6종 및 매핑된 3상태 성능을 평가한다. 기존 L02/L03/R02/R03 등 튜닝 조건은 대표 비교에 넣지 않는다.

새 신경망 5조건×seed 2026,2027,2028 = 15회. FMLP3는 18→128 ReLU→64 ReLU→3 logits, Dropout 0. 시계열 신경망은 기존 M01/C01/R01/L01의 몸통과 Dropout을 유지하고 최종 logits만 3개로 변경한다. CNN만 Dense 뒤 Dropout 0.3. 기존 모델과 가중치가 일치한다고 주장하지 않는다.

공통 Adam 0.001, batch 64, 최대 40 epoch, patience 6, min_delta 0, validation loss 최저 가중치 복원, 희소 교차엔트로피(from_logits=True), CPU intra-op 4/inter-op 1. 각 학습은 별도 프로세스에서 순차 실행한다. 각 seed 모두 보고하며 최고 seed를 선택하지 않는다. 추가 하이퍼파라미터 탐색이나 목표 점수를 정하지 않는다.

LR3/LR6는 기존 고정 대조의 저장 계수와 특징 표준화 통계를 그대로 사용한다(L2, C=1, lbfgs, tol=1e-8, max_iter=2000). 반복 초기화가 없는 LR에 seed SD를 만들지 않는다.

## 데이터와 특징

기존 fit 16명 5,577구간 / val 5명 1,775구간을 유지한다. 학습 배열에서 산출된 팀 seq_mean/seq_std를 한 번 적용한다. 18개 특징은 표준화된 9채널 각각 시간축 평균과 모집단 표준편차(ddof=0)이다. 특징의 추가 표준화는 기존 LR 모델의 fit-only mean/scale을 FMLP3에도 동일하게 사용한다. LR은 float64, 신경망 입력은 float32로 계산한다. PCA나 test 통계 재추정은 없다.

3상태 매핑은 [0,0,0,1,1,2]: 걷기·계단 오르기·내리기→이동, 앉기·서기→앉거나 서 있음, 눕기→누워 있음. 6종 모델은 argmax 후 매핑한다. 새 모델은 3상태 정답으로 직접 학습한다.

## 검증과 비용 측정

새 모델은 전체 validation 예측을 저장하고 새 프로세스에서 재로딩한 결과가 클래스 일치 및 확률 rtol=1e-5, atol=1e-6 이내인지 검사한다. 기존 저장 모델도 공개 validation 예측과 동일 기준으로 대조한다. 중앙차분 등 이미 완료된 LSTM 수학 검증은 재사용한다.

비용 측정은 동일 PC CPU, batch 1, validation의 첫 구간, 워밍업 50회 후 500회이다. 준비된 센서 구간 이후의 표준화·필요한 특징 추출·모델 호출·확률/클래스 반환을 포함한 시간과, 준비된 모델 입력 이후 호출 시간을 분리한다. 데이터 수집, UCI의 필터링·윈도 생성, 파일 읽기, 초기 모델 로딩, 첫 tracing은 제외한다. TensorFlow는 tf.function을 사용한다. LR는 NumPy 행렬 연산을 사용하므로 결과는 실행 구성 전체의 PC 측정이지 알고리즘이나 스마트폰 전력 비교가 아니다.

가중치/전처리 수치 배열 바이트, 추론 저장 파일 바이트, 준비 이후 프로세스 RSS와 측정 중 관측 최대 RSS를 구분한다. RSS에는 Python/TensorFlow 런타임이 포함되므로 순수 모델 메모리라고 표현하지 않는다. 한 번에 한 모델만 실행하고 다른 학습과 동시 측정하지 않는다.

## 공식 test 개봉 전 고정

개발 학습·재로딩 검증·비용 측정을 먼저 완료한다. 그 뒤 프로토콜, 설정, 학습/평가 코드, 저장 모델, 통계, 개발 지표와 예측, 비용 결과의 SHA-256 및 평가 대상 목록을 FINAL_LOCK.json에 저장하고 Git 커밋한다. 평가기는 lock의 내용과 모델 해시를 검증하기 전 test 배열을 로딩할 수 없게 한다.

공식 test는 기존 캐시의 test_Xs/test_y/test_subject/test_sample_id를 로딩한다. 원본 UCI 파일의 9채널, 라벨, 사람과 캐시의 원 행 번호(0 시작)를 대조하고, fit/val 사람과 ID 비중복·shape·유한성·라벨 범위를 확인한다. 모델은 16명 fit으로 학습하고 5명 val로 epoch를 선택한 그대로 사용한다. test 이전에 fit+val로 재학습하지 않는다.

모든 고정 구성의 6종/3상태 Accuracy, Macro F1, 클래스별 지표·혼동행렬, 사람별 성능과 표본 수, 오분류 ID를 저장한다. NN은 세 seed 평균과 표본 SD, 같은 seed의 차이를 보고한다. SD는 사람 모집단 신뢰구간이 아니다. 60개 매핑의 새 검색은 test에서 하지 않는다. 평가 후 모델 수정·seed 선택·threshold 조정 없이 결과를 보고한다.

저장 예측에서 독립적으로 지표를 재계산하고 전체 모델을 새 프로세스에서 재예측하는 것은 재현성 확인이며 재튜닝이 아니다. 실패는 로그와 실패 상태를 보존하고 변경 이유를 기록한다. test 성능 관찰 후 발견한 문제는 사전 문제와 분리한다.
