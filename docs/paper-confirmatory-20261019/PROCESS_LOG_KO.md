# 실행 과정 기록

## 2026-10-19: 추가 실험 시작

- 사용자 요청으로 기존 공식 test 보류를 해제했다. 다만 개발 비교와 비용 측정을 마친 후 조건을 고정하고 평가하는 순서를 유지한다.
- 기존 원고의 입력 표현·학습 목표 차이를 해소하기 위해 FMLP3와 시계열 직접 3상태 조건 네 개를 고정했다. 기존 모델 구현은 수정하지 않고 추가 실행 도구에서 출력층을 변경한다.
- 프로토콜·설정·평가 도구·새 테스트를 커밋 `f45d70b`로 저장한 뒤 정식 학습을 시작했다.
- 사전 코드 검사 3개 통과: 다섯 구조의 3-logit 출력, 통계 특징과 지표의 독립 계산, lock 부재·변조 시 test 로딩 차단.
- 기존 MLP/RNN 저장 모델은 체크아웃에 없어 공개 Release 묶음에서 복원했다. 압축파일 SHA-256과 각 모델의 기존 metadata SHA-256을 대조해 6개 모두 일치했다. 재학습하거나 다른 모델로 대체하지 않았다.
- NPZ에서 test 항목의 키·헤더(shape/dtype)만 확인했다. 개발 단계에서는 test 센서값·라벨·사람 ID 배열을 로딩하지 않는다.
- Keras의 `shuffle=True` 무시 경고가 출력됐다. 입력이 tf.data.Dataset이며 `make_dataset` 내부에서 seed를 지정해 shuffle하는 구조이므로 경고가 학습 미섞임을 의미하지 않는다. 기존 순서·설정을 바꾸거나 이를 실제 오류 해결 사례로 포장하지 않는다.
- test 개봉 전에 재현 환경의 경로 이식을 위해 `HAR_PROCESSED_DATA` / `HAR_OFFICIAL_ROOT` 환경변수를 추가했고, 최종 lock에 기존 모델 설정 JSON도 포함하도록 했다. 학습 함수·모델·특징·하이퍼파라미터는 변경하지 않았다. 실행 중인 원래 경로는 동일하다.

## 전체 테스트 실행 경로 문제 (test 개봉 전)

- 재현 입력: 저장소 상위 작업공간에서 `python -m pytest outputs/smartphone-har/tests` 실행.
- 관찰: test_cnn 수집 중 `ModuleNotFoundError: No module named 'src'`. 테스트 수집에서 중단되어 모델 학습·평가를 실행하지 않았다.
- 원인: 기존 테스트가 저장소 루트를 Python import 경로로 사용하는 실행 방식을 전제로 한다.
- 수정: 모델·테스트 코드를 바꾸지 않고 작업 디렉터리를 저장소 루트로 지정해 `python -m pytest tests`로 실행했다.
- 첫 실패 기록: `reports/confirmatory_20261019/tests_collection_failed.xml`. 재실행 결과는 `tests.xml`에 별도 저장한다.

## 개발 단계 완료 (공식 test 개봉 전)

- 추가 학습 15/15회 완료. 별도 프로세스에서 seed 3개씩 실행했고 학습 결과를 교체하지 않았다.
- 저장소 루트 재실행 결과 기존·신규 테스트 71개 모두 통과했다. 수집 실패는 실행 경로 차이였으며 모델 코드를 수정해 통과시킨 것이 아니다.
- 기존 모델 12개·새 모델 15개·선형 모델 2개, 총 29개 모두 전체 validation 1,775개에서 예측 클래스 일치 및 확률 rtol=1e-5, atol=1e-6을 통과했다.
- 29개 모델의 비용을 각각 새로운 프로세스에서 순차 측정했다. 학습과 동시 실행하지 않았다. 각 프로세스 50회 워밍업·500회 측정, 두 범위(준비된 입력 이후 / 센서 구간부터 출력까지)의 원시 기록과 메모리를 보존했다.
- 현재 환경은 Python 3.11.9, TensorFlow 2.21.0, Keras 3.15.1, NumPy 2.2.6, Intel Family 6 Model 183 CPU다. 기존 모델 학습 당시 Python·CPU와 다르므로 과거 시간 측정치를 재사용하지 않았다.
- 실제 학습 당시 소스 해시 2종(14회/1회)을 정확한 바이트로 보존했다. 경로 환경변수 추가 외 학습 함수는 동일하다. 최종 평가 소스에는 설정·드라이버·학습 소스 스냅샷을 lock에 포함하는 기능을 추가했다.
