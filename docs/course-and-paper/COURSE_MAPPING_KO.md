# 인공지능 공학 수업 발표와 공동 논문 활용 안내

작성 2026년 10월 9일. 담당 이봉헌. 같은 스마트폰 행동 인식 프로젝트를 수업 평가와 학술 발표에 활용한다. 수업은 이해·설계·검증 과정을, 공동 논문은 같은 조건에서 확인한 결과와 연구의 한계를 중심으로 설명한다. 두 자료의 실험 수치와 역할 표기는 일치시킨다.

## 확인한 수업 요구

제공 폴더의 수업 OT 2쪽은 미분·연쇄법칙·오류 역전파 이해, TensorFlow/Keras 구현, 공개 데이터의 전처리·평가·시각화 팀 프로젝트를 학습 목표로 제시한다. OT 14쪽의 발표 예시는 데이터 구성, 구축 목적, 구축·튜닝, 시연, 성능 평가와 질의응답이며 약 30분이다. 이 시간과 4인 구성은 예시로 읽고, 실제 팀의 확정 역할 5명을 유지한다. 별도 과제 공지로 확정된 개인 발표 시간은 확인하지 않았다.

OT 10쪽의 AI 코드 검증·디버깅 취지에 맞춰, Codex 도움으로 만든 코드와 문서를 실행·검산한 근거를 보여준다. 자동 생성 여부를 숨기지 않고 수식, 코드와 결과를 직접 설명할 준비를 한다. 강의자료 원문과 PDF는 저장소에 배포하지 않는다.

## 커리큘럼과 LSTM 작업의 연결

| 수업 항목 | 자료의 실제 위치 | 봉헌님의 설명과 근거 | 수업 PPT |
|---|---|---|---|
| 미분과 수치미분 | 신경망 기초 이론 16쪽 | 58개 파라미터의 중앙차분 174회 검산 | 8~9장 |
| 편미분과 연쇄법칙 | 신경망 기초 이론 21~22·30쪽 | 게이트의 국소 미분과 셀 상태 기울기 누적 | 5~8장 |
| 지도학습과 표현 | 기계학습과 인식 11~12쪽 | 128×9 구간으로 여섯 행동 분류, 사람 분리 | 3~4장 |
| 활성화와 softmax | 신경망 기초 29~32쪽 | sigmoid 게이트, tanh 후보, Dense ReLU, logits 손실 | 5~7장 |
| 성능 측정 | 기계학습과 인식 49~55쪽 | Accuracy·Macro F1, 개발 validation과 최종 test 구분 | 13~14·18장 |
| 하이퍼파라미터 | 신경망 기초 41~44쪽 | 은닉 크기·외부 Dropout의 사전 조건 비교 | 11~13장 |
| TensorFlow 구현 | OT 6쪽의 6~7주 진도표 | 모델 저장·재로딩, 입력 검증과 예측 시연 | 10~11·15장 |
| 시계열 RNN과 LSTM | OT 6쪽의 10주 주제 | 마지막 은닉 상태, 구간별 상태 초기화 | 4~6장 |

RNN/LSTM 상세 강의 PDF는 이 폴더에 없어 OT 진도표와 Keras 공식 문서를 연결했다. AE·GAN·강화학습 등 다른 주제의 수행 결과로 이 LSTM 작업을 확대하지 않는다. 기존 10주 프로젝트 계획서의 추가 실습안은 현재 확정된 담당 범위와 구분한다.

## 발표 시간과 팀 연결

개인 심화 설명은 본문 15장 약 10~12분, 부록 5장은 질문 때 사용한다. 팀 전체 약 30분 구성의 제안은 데이터 5분, MLP 5분, CNN 5분, RNN 5분, LSTM 8분, 공동 결론 2분이다. 팀원별 실제 발표 시간은 아직 합의하지 않았다. LSTM 8분 버전은 1·3·4·5·7·9·11·12·13·15장을 중심으로 설명하고 상세 BPTT와 전체 결과는 질문에서 사용한다.

## 시연 방법

RUN_DEMO_KO.md의 명령으로 저장한 L01 seed 2026 모델을 로딩해 validation 구간 다섯 개를 분류한다. 준비된 UCI 구간을 입력하는 오프라인 시연이다. 스마트폰 센서 실시간 수집·앱 시연이나 공식 test 평가로 소개하지 않는다. 이전에 기록한 실제 결과는 demo_predictions.json에 보관한다. 실행 당일에는 새 출력 경로를 지정한다.

## 수업 자료와 논문 자료의 관계

수업 발표의 수식·구현·검증 과정은 팀 연구의 개인 수행 근거다. 논문에는 분량에 맞춰 데이터, 실제 모델 구조, 공통 실험 조건, 비교 결과와 한계를 넣는다. 이미 같은 프로젝트로 수업에서 발표했다면 그 사실을 일관되게 설명한다. 수업 발표가 정식 논문집으로 출판되는 경우에는 해당 공개 이력을 투고 규정에 따라 별도로 확인한다.

UCI·LSTM 원 논문·공식 API의 설명은 본문과 발표 노트에서 출처를 연결한다. 팀원 결과는 담당자 검토 후 취합한다. 실제 결함, 입력 인터페이스 차이, 의도적 오류 주입을 구분한다. 문서 유사도 검사나 모든 선행 연구 조사가 완료되었다고 주장하지 않는다.
