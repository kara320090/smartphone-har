### 2. 활동 기록에서 필요한 출력 (0:20–0:55)

스마트폰 센서로 활동을 기록할 때 모든 서비스가 같은 출력을 요구하지는 않습니다. 현재 이동 중인지, 앉거나 서 있는지, 누워 있는지를 요약하려면 세 상태가 필요합니다. 반면 좌식 시간이나 계단 이용을 구분하려면 여섯 행동의 세부 정보를 보존해야 합니다. 저희는 이 출력 요구가 모델 선택에 어떤 차이를 만드는지 비교했습니다.

**설명할 때 기억할 점:** 활용 예시는 분류 결과를 연결할 출력 설계다. 기록 앱의 효과나 하루 지속시간 측정 결과로 제시하지 않는다. 누워 있음은 자세 라벨이다.

### 5. 출력 목표와 입력 특징의 대조 (2:00–2:40)

첫 번째 방법은 여섯 행동을 학습한 모델의 최종 예측을 세 상태로 바꿉니다. 확률을 그룹별로 더하는 방식이 아니라 여섯 클래스 argmax의 라벨을 매핑합니다. 두 번째는 처음부터 세 상태를 직접 학습합니다. 별도로 아홉 채널의 평균과 표준편차, 총 열여덟 특징을 만들고 LR과 특징 MLP에 동일하게 제공했습니다. 신경망은 세 seed를 모두 보고했습니다.

**설명할 때 기억할 점:** 6종 argmax 병합과 그룹 확률 합산은 다른 의사결정 규칙이다. 고정 비교에서는 전자를 사용했다. 특징 표준화 통계도 LR3·FMLP3에서 동일하다. LR float64, MLP float32 및 최적화 차이를 포함한 구성 대조다.

### 6. 직접 학습의 평균 F1이 네 NN에서 높았다 (2:40–3:20)

동일한 세 상태 과제에서 직접 학습의 평균 F1이 네 신경망 모두에서 높았습니다. MLP는 0.9796에서 0.9918, LSTM은 0.9866에서 0.9959로 높아졌습니다. CNN은 이미 병합 점수가 높아서 차이가 작습니다. 이 결과는 출력 목표에 맞춘 학습의 이점을 보여줍니다. 여섯 클래스와 세 클래스의 숫자를 바로 비교해 모델 자체가 좋아졌다고 해석하지는 않습니다.

**설명할 때 기억할 점:** 같은 사람이 포함된 test에서 세 seed의 평균을 비교한다. 구조·최적화 설정을 포함한 실증적 결과이고 유의성이나 모든 데이터셋의 우월성을 주장하지 않는다.

**근거:** https://github.com/kara320090/smartphone-har/blob/8b68cb251084ac7ced2557d9472f0889a1d5a45b/reports/confirmatory_20261019/summary.csv

### 7. 같은 seed 12쌍 중 11쌍에서 F1 증가 (3:20–3:55)

평균만으로 결론을 내리지 않고 같은 seed의 차이를 확인했습니다. 열두 쌍 중 열한 쌍이 증가했고, LSTM의 2027 seed는 약 0.0011 감소했습니다. 따라서 직접 학습이 매번 더 좋다고 말하지 않습니다. 이 고정 조건에서 평균 개선 경향을 관찰했다는 결론입니다. 세 seed의 변동도 새로운 사람 전체에 대한 신뢰구간과 구분했습니다.

**설명할 때 기억할 점:** 양수 개수는 paired_differences.csv에서 계산했다. 음수 항목도 그대로 보존했다. 3seed 반복을 근거로 통계적 유의성·동등성 결론을 내리지 않는다.

**근거:** https://github.com/kara320090/smartphone-har/blob/8b68cb251084ac7ced2557d9472f0889a1d5a45b/reports/confirmatory_20261019/paired_differences.csv

### 8. 직접 3상태의 높은 F1과 모델 규모 (3:55–4:30)

직접 세 상태의 구성별 F1은 0.9905에서 0.9994로 모두 높았습니다. 신경망은 세 seed의 평균, LR은 단일 학습 결과입니다. 따라서 작은 점수 차이로 LR의 우월성을 결론 내리기보다, 높은 성능을 보인 구성의 비용을 비교했습니다. 같은 열여덟 특징의 LR3와 특징 MLP는 파라미터가 57개와 10,883개였습니다.

**설명할 때 기억할 점:** 구성별 대표 F1의 범위이며 모든 seed의 F1이 0.99 이상이라는 뜻은 아니다. LR3와 FMLP3의 점수 차이는 약 0.00085이다. 통계적 동등성이나 우월성을 검정한 결과로 제시하지 않는다. 57은 18×3+3이며 표준편차 특징 계산은 원 시계열에 대한 비선형 변환이다.

**근거:** https://github.com/kara320090/smartphone-har/blob/8b68cb251084ac7ced2557d9472f0889a1d5a45b/reports/confirmatory_20261019/summary.csv

### 9. 준비된 구간의 CPU 처리 비용 (4:30–5:05)

같은 i9-13980HX CPU에서 준비된 한 구간의 처리 시간을 측정했습니다. 표준화, 특징 계산, 분류, 결과 반환을 포함해 LR3는 0.073밀리초, 특징 MLP는 1.043밀리초로 약 14.2배 차이였습니다. 높은 F1을 보인 두 구성의 비용 차이입니다. 이 값에는 NumPy와 TensorFlow 구현 차이도 포함되며, 입력을 모으는 2.56초와 별개입니다.

**설명할 때 기억할 점:** CPU intra 4/inter 1, 고정 validation 첫 구간, 순차 benchmark. 수집·UCI 필터링·구간화·초기 로딩 제외. 스마트폰 장치의 응답시간이나 배터리 성능으로 확대하지 않는다.

### 10. LR3의 오류는 2개 구간에서 발생 (5:05–5:35)

높은 전체 점수에서도 오류를 확인했습니다. LR3는 공식 테스트 2,947구간 중 두 구간을 틀렸습니다. 모두 사람 9의 앉기 구간을 이동으로 예측한 경우입니다. 두 원 행은 서로 인접하고 중첩하므로 독립된 실패 사건 두 번이라고 해석하지 않습니다. 이처럼 점수와 함께 오류가 어느 사람과 구간에 있는지 추적할 수 있게 남겼습니다.

**설명할 때 기억할 점:** Accuracy=2945/2947=0.9993213437, Macro F1=0.9994336884. 오류 원인은 이 예측만으로 자세·센서 이동 등으로 확정하지 않는다.

### 11. 실제 센서 구간의 상태 태그 예시 (5:35–6:15)

여기는 실제 테스트 구간의 신체 가속도 세 축입니다. 원래 걷기인 이 구간에 고정된 LR3가 이동이라는 태그를 반환했습니다. 이런 구간별 출력을 활동 요약 모듈의 상태 표시에 연결하는 활용 설계입니다. 카메라나 GPS 없이 센서 입력을 사용합니다. 좌식 시간이나 계단 이용처럼 세부 정보가 필요한 서비스는 해당 라벨을 유지해 선택합니다.

**설명할 때 기억할 점:** 고정 LR3 예측 파일에서 원 행 순서상 첫 정분류 이동 표본 test:000079를 예시로 선택했다. 정답과 예측을 이미 저장한 파일에서 읽었으며 재튜닝하지 않았다. 입력은 UCI 처리 후 팀 표준화 전의 body_acc_xyz, 단위 g이며 시간 좌표는 0~2.54초(128샘플 창 길이 2.56초)다. 하나의 정분류 예시는 전체 성능 근거와 구분한다. 실제 결과는 슬라이드 8·10 및 부록 1에 제시했다. 앱 운영 효과나 하루 지속시간 수치로 제시하지 않는다.

### 12. 결론 (6:15–7:00)

정리하겠습니다. 직접 세 상태는 모든 구성에서 높은 F1을 보여, 작은 점수 차이보다 처리 비용이 선택의 추가 근거가 됐습니다. 같은 특징의 LR3와 특징 MLP는 높은 F1에서 PC 처리 시간이 약 14.2배 차이 났습니다. 반면 여섯 행동에서는 CNN의 F1이 0.9053, LR6가 0.7486으로 결과가 달라졌습니다. 필요한 행동 정보를 먼저 정하고, 그 목표의 성능과 비용으로 분류 구성을 선택하는 것이 저희 연구의 결론입니다. 감사합니다.

**설명할 때 기억할 점:** NN은 seed 평균, LR은 단일 적합의 대표 F1을 비교한다. 고정 조건의 관측 성능과 비용을 근거로 삼고, LR의 보편적 우월성 또는 통계적 성능 동등성으로 해석하지 않는다. 기존 사사 문구와 번호를 그대로 유지했다.

- 구성별 F1 범위는 NN의 3 seed 평균과 LR 단일 적합 결과다. 모든 seed가 0.99 이상이라는 뜻은 아니다.
